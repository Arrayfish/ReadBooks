# Reference: Issue テンプレート（Backlog なし）

## GitHub Issue 本文テンプレート

```markdown
## 概要

<!-- 1〜3文で何をするか -->

## 背景・目的

<!-- なぜ必要か -->

## 実装タスク

- [ ] タスク 1（ファイル・モジュールが分かれば記載）
- [ ] タスク 2

## 受け入れ条件

- [ ] 条件 1（テスト名・手動確認手順を明示）
- [ ] 条件 2

## スコープ外

- 今回やらないこと

## 制約・方針

- 変更は最小限
- 既存のコーディング規約・レイヤー構造に従う
- 新規依存の追加は理由を Issue に書く

## 参照

- 仕様・設計: （ユーザー提供のドキュメント URL やファイルパス）
- 関連 Issue / PR: （あれば）

## 確認事項（未確定がある場合のみ）

- 質問 1
```

## タイトル例

| 種別 | 例 |
|------|-----|
| 機能追加 | `feat: 運行記録一覧に日付フィルタを追加` |
| バグ修正 | `fix: 日常点検保存時のバリデーションエラー` |
| リファクタ | `refactor: driver コントローラの重複処理を整理` |

## ラベル（このリポジトリ）

特に指定がなければ `enhancement`（機能）または `bug`（不具合）。ユーザー指定を優先。

## `gh issue create` 例

```bash
cat > /tmp/agent-issue-body.md <<'EOF'
（テンプレートを埋めた本文）
EOF

gh issue create \
  --title "feat: 〇〇 API にフィルタを追加" \
  --body-file /tmp/agent-issue-body.md \
  --label "enhancement"
```
