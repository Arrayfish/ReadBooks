# テストの作成

- pytest を使う

## テストの命名

- テストの関数名は、`test_` で始める
- テスト関数名は非開発者に何を検証しているのかがわかるようにする

## テストの場所

- テストの場所は、tests/以下のそのモジュールと同じ階層に置く
- 例えば、`app` ディレクトリ以下に `app/foo/bar.py` がある場合、テストファイルは `tests/app/foo/test_bar`ディレクトリに置く
- 同じメソッドのテストは一つのファイルにまとめる
- 例外的にAPI呼び出しを行う結合テストを作成する場合は`tests/app/API`以下にファイルを作成する

## テストの種別

次の4種類のテストを作成する

- ユニットテスト: ドメイン層(Always-valid layer)のドメインロジックをメソッド単位でテストする。C1網羅性を担保する。
- ユニットテスト(その他): ドメイン層以外のロジックをテストする。
- 統合テスト: アプリケーション層のロジックをテストする。正常系一つと全ての異常系のテストを行う。
- API(E2E)テスト: ユーザーが使うようなAPIをテストする。できるだけ多くの分岐を通過する正常系一つと、想定する全てのエラーを1回ずつテストする。

## テストヘルパー

- DBを使うテストの場合はdb_sessionフィクスチャーでsqlalchemyのセッションが入手可能
- DBを使うテストでsqlalchemyのエンティティをテストで利用する場合はそれぞれのエンティティを確認してcreate_sample()クラスメソッドがあれば利用

## テストコードの例

```python
def test_2_add_3_is_5():
  """2+3は5となる"""
  assert add(2, 3) == 5
```

アサーションの書き方

- `assert a == b` で可能な限り期待する動作を書く

## テストの実行方法

`uv run pytest <args>`
